# benPilot application branding

The application calls itself **benPilot**, with version `0.9.8(v3.18)-benPilot.1`, a `BenPilotTogglesPanel`, renamed settings/help/welcome and unavailable/disengagement/cancellation alert text, and a visible Software-screen credit to **jvePilot by John Van Etten**, based on comma.ai openpilot. Legal terms, upstream service identities, asset paths, stored `jvePilot.settings.*` keys, and serialized log/schema identifiers are retained. Existing translations retain their text with only the product-name substitution in the affected UI contexts; legal/service wording stays untouched. Alert triggers, priorities, sounds and durations stay unchanged. No settings migration, parameter reset, controller change or warning suppression is part of this rename. The separate `benPilot-release` alias has exactly the original July release flags, preserving existing release-only behavior; all existing channels and the upstream/fork identity check remain unchanged.

`verify_branding.py` compares the affected production files with exact permitted text/class substitutions against the original July commit. Recovery scope verification still rejects changes to control logic, safety code, models, firmware, OS requirements, parameter definitions and schemas. The installer patch remains separately checked.

`build-ui.sh` compiles the actual comma-three QCOM2/larch64 `selfdrive/ui/ui` target from an exact reviewed commit in a network-disabled, capability-dropped ARM64 container. Ubuntu Mesa requires an explicit `libGL` link for `glEGLImageTargetTexture2DOES`; two EGL KHR procedures also need the host-only `ubuntu-egl-dispatch.cc` adapter, which dispatches to the real Mesa extension procedures via `eglGetProcAddress` and aborts if unavailable. The reviewed `ubuntu-ui-linkage.patch` adds only these host link dependencies in the disposable checkout, with its applied diff saved in build evidence. The UI binary is named `benpilot-ui-ubuntu-compile-check` and depends on this separate host-only library; neither is a device deployment artifact. The actual UI and adapter entry points are never executed by CI. Production build rules remain unchanged. This host-linked UI is compile evidence, not an AGNOS deployment binary or ABI validation. It does not start the UI, connect to a device, generate a complete driving-stack image or perform installation. `smoke_brand.py` executes only the actual small Qt `getBrand()` helper and checks the version, panel class and origin credit in the compiled binary; it never initializes hardware or the UI service.

The existing July installer candidate deliberately remains pinned to the original July source. It will not install this newly branded application. The separate branded candidate pins `benPilot-release` at `2a8c27188bf10021736621bab4ce6975fc38edcc`, retaining existing OS/model/source guards. It still requires the backup/compatibility/rollback review before any device use. Earlier published installers are not silently repointed.

Native Qualcomm model generation, inherited safety-test disagreements and actual device ABI/UI validation remain pending. Device work requires the existing SSH target and parked confirmation, verified private full-state/settings backup and rollback, then the required installation confirmation.
