# benPilot application branding

The application calls itself **benPilot**, with version `0.9.8(v3.18)-benPilot.1`, a `BenPilotTogglesPanel`, renamed settings/help/welcome and unavailable/disengagement/cancellation alert text, and a visible Software-screen credit to **jvePilot by John Van Etten**, based on comma.ai openpilot. Legal terms, upstream service identities, asset paths, stored `jvePilot.settings.*` keys, and serialized log/schema identifiers are retained. Existing translations retain their text with only the product-name substitution in the affected UI contexts; legal/service wording stays untouched. Alert triggers, priorities, sounds and durations stay unchanged. No settings migration, parameter reset, controller change, release-channel classification or warning suppression is part of this rename.

`verify_branding.py` compares the affected production files with exact permitted text/class substitutions against the original July commit. Recovery scope verification still rejects changes to control logic, safety code, models, firmware, OS requirements, parameter definitions and schemas. The installer patch remains separately checked.

`build-ui.sh` compiles the actual comma-three QCOM2/larch64 `selfdrive/ui/ui` target from an exact reviewed commit in a network-disabled, capability-dropped ARM64 container. Ubuntu Mesa requires an explicit `libGL` link for `glEGLImageTargetTexture2DOES`; the reviewed `ubuntu-ui-linkage.patch` adds only that dependency in the disposable checkout, with its applied diff saved in build evidence. Production build rules remain unchanged. This host-linked UI is compile evidence, not an AGNOS deployment binary or ABI validation. It does not start the UI, connect to a device, generate a complete driving-stack image or perform installation. `smoke_brand.py` executes only the actual small Qt `getBrand()` helper and checks the version, panel class and origin credit in the compiled binary; it never initializes hardware or the UI service.

The existing July installer candidate deliberately remains pinned to the original July source. It will not install this newly branded application. A later branded installer must explicitly pin a reviewed branded payload, retain the existing OS/model/source guards, and undergo the backup/compatibility/rollback review before any device use. No published installer is silently repointed by this change.

Native Qualcomm model generation, inherited safety-test disagreements and actual device ABI/UI validation remain pending. Device work requires the existing SSH target and parked confirmation, verified private full-state/settings backup and rollback, then the required installation confirmation.
